# 升级与回滚

退出目标工程Editor。保留原版本套件及工程备份，使用新套件 `release-tool.py install <new-suite> <project>`，不加 --sample。工具检查受管包每个原文件摘要，拒绝手工变更和无状态的包；仅允许Unity生成的额外.meta，不接受其他未知文件。用户定制请移到项目自有代码，不直接修改发行包。

依赖冲突立即停止，不静默升级第三方。安装将新包先暂存、旧包留事务备份，失败恢复包和manifest；原packages-lock.json由UPM下一次解析更新，不由工具改写。运行中Editor不能安装，应先关闭避免UPM并发。

完成后验证旧消费者重编译、行为、序列化引用与用户存档。样例是导入后的用户资产，升级不会覆写它。更新样例需显式比较/迁移，不重复导入相同GUID。

回滚用 `release-tool.py install <old-suite> <project>`。回滚仅替换框架包，用户文件与存档不回滚；若新游戏schema不可逆，需用户数据恢复策略，不能承诺框架回滚恢复所有业务数据。

已完成0.1.2→0.1.3→0.1.2实际演练：旧版在空白工程创建消费者及样例存档，新版读取并通过功能回归和Mono Player运行，再回滚旧版读取。71个消费者/样例/ProjectSettings/存档文件摘要一致。0.1.0编译失败，0.1.1消费者样例用例未发现，均不作为有效升级基线。同版本内容不允许重新发布，跨依赖/引擎/平台升级不因本演练自动获得支持。

本次回滚包与安装状态已提交，但事务备份清理被IDE审批中断；用户确认后独立回滚消费者测试2/2通过，残留备份保留并单列警告，不修改原失败报告。清理失败不等于安装/回滚没发生：先核对Packages/minigame-install.json、包内容与原存档，不能无条件重装或删除整个工程。
